The problem

A language model on its own will answer a question about your coursework confidently and sometimes wrongly, and it cannot tell you which it is doing. For anything a student might rely on, that is disqualifying. The useful version is a model that is restricted to material you gave it and can point back at the source.

What I built

A retrieval-augmented generation pipeline in LangChain: documents are chunked and embedded, a question retrieves the passages closest to it, and only those passages go to the model as context. Query comprehension improved by 25% against our test set. I added multi-file input so a user could load a whole semester of notes at once rather than one PDF at a time, which was the change that moved satisfaction most.

Where the interface work was

The design problem in a RAG system is not the chat bubble. It is calibrating trust. A user needs to know when the answer came from their documents and when the model is improvising, because those two answers deserve very different levels of confidence. Showing retrieved sources alongside the response does more for usability than any amount of conversational polish, and it is the thing I would build first if I started again.

An answer with no visible source asks the user to trust it completely or not at all. Neither is a reasonable thing to ask.

Ethics, concretely

Through the club's AI for Social Good projects I worked on ethical deployment in education, which in practice meant arguing about specifics rather than principles: what the system should refuse to answer, how to keep it from doing a student's assignment outright, and how to make its limits visible rather than discovered by accident.

What I took from it

That the hardest interface problems in AI are about uncertainty. A system that is honest about what it does not know is more useful than one that is right slightly more often, because only the first kind can be relied on.
